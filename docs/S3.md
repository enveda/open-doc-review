# Amazon S3 adapter (example)

> **Example adapter, not tested against a live system.** It follows the Amazon S3 API reference
> and is tested against a fake client only. Try it on a test prefix with `review.dry_run: true`
> first. Every assumption it makes is listed under [Known limits](#5-known-limits).

The adapter connects open-doc-review to documents under one prefix of an S3 bucket.

S3 objects are immutable. Changing an object's metadata means copying the object over itself,
and this adapter never does that. Instead, each document's namespaces and comments live in a
**sidecar object**, `<key>.docreview.json`, the same way the local adapter keeps a sidecar file.
The adapter's only write is a `PutObject` of a sidecar. It never puts, copies or deletes a document.

```bash
pip install 'open-doc-review[s3]'   # adds boto3
```

## 1. IAM policy

Credentials come from the default boto3 chain: environment variables, a profile, or an instance
or task role. You can restrict writes to sidecars at the IAM level, so the policy itself guarantees
that documents are never written:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {"Effect": "Allow", "Action": ["s3:ListBucket", "s3:ListBucketVersions"],
     "Resource": "arn:aws:s3:::docs", "Condition": {"StringLike": {"s3:prefix": ["lib/*"]}}},
    {"Effect": "Allow", "Action": ["s3:GetObject", "s3:GetObjectVersion"],
     "Resource": "arn:aws:s3:::docs/lib/*"},
    {"Effect": "Allow", "Action": "s3:PutObject",
     "Resource": "arn:aws:s3:::docs/lib/*.docreview.json"}
  ]
}
```

Add `kms:Decrypt` (and `kms:GenerateDataKey` for the sidecar puts) if the bucket uses SSE-KMS.

## 2. Configure

```yaml
ecm:
  adapter: s3
  options:
    bucket: docs
    prefix: lib/                 # nothing outside this prefix is read, found or written
    inbox_prefix: lib/inbox/     # what poll lists; default = prefix
    # sidecar_prefix: _review/   # default = prefix, so the sidecar sits next to its document
    # use_version_id: true       # on a versioned bucket
    region: eu-west-1
```

| Option | Default | Meaning |
|---|---|---|
| `bucket` | (required) | The bucket. |
| `prefix` | `""` | Key prefix that scopes everything; empty, or ending in `/` (so `lib/` never covers `library/`). A document's id is its full key. |
| `inbox_prefix` | `prefix` | Prefix that `poll` lists. It must start with `prefix` and end in `/`. |
| `recursive` | `false` | Also list keys below the inbox's direct "folder". |
| `sidecar_prefix` | `prefix` | Where sidecars go (empty, or ending in `/`). The sidecar of `<prefix><rest>` is `<sidecar_prefix><rest>.docreview.json`. |
| `use_version_id` | `false` | Use the VersionId as the version, and download that exact version. This needs bucket versioning. |
| `region` | the boto3 default | Region for the client. |

Keys that end in `/` (folder markers) or in `.docreview.json` are never treated as documents. Every port
method refuses a key outside `prefix`.

Run `docreview check`. It reaches the bucket (`HeadBucket`) and lists the inbox. With
`use_version_id`, it also confirms that versioning is enabled.

## 3. How the port maps to S3

| Port method | S3 API |
|---|---|
| `poll` | Lists the inbox (paged), then reads each document's sidecar and applies the offer rule. With `use_version_id` it lists with `ListObjectVersions` (latest versions only), because `ListObjectsV2` doesn't return VersionIds. Otherwise it uses `ListObjectsV2` with `Delimiter=/` unless `recursive`. A sidecar that is not valid JSON is skipped with a warning (as the local adapter does); fix or remove it. There is no cursor: the sidecars are the state. |
| `get` | `HeadObject`. The version is the ETag (without quotes), or the VersionId. |
| `download` | `GetObject`, pinned. With `IfMatch=<ETag>`, a changed object fails with 412 and the adapter raises. With `VersionId=` it reads exactly that version. |
| `read_metadata` / `write_metadata` | `GetObject` / `PutObject` of the sidecar. A write merges into the namespace, and `None` removes a key. The put is **conditional**: `IfNoneMatch=*` when the sidecar is new, `IfMatch=<ETag>` otherwise. On a conflict (412) the adapter re-reads and retries, up to 3 times, so a concurrent edit is never lost. |
| `find` | Lists every sidecar under `sidecar_prefix`, reads each one, and filters in Python. A match has the same `doc_type`, and every value is equal after trimming surrounding whitespace and folding case; numbers compare as numbers. A sidecar that is not valid JSON is skipped with a warning. Each hit is checked with `HeadObject`, and a sidecar whose document is gone is skipped. Results are newest first. `scope` is a parent "folder" (`lib/po/`), matched exactly. |
| `post_comment` / `list_comments` | Appends to the sidecar's `comments` list, with the same conditional put. |

## 4. Re-review and late references

S3 has no metadata field a person can tick. To ask for a re-review, do one of these:
- run `docreview review <key>`;
- download the sidecar, set `"review": {"requested": true}`, and upload it again.

A review result clears the request.

A document reviewed before its reference arrived is re-reviewed automatically once the reference
is processed, for rules whose `match` values are bare `{field}` placeholders.

## 5. Known limits

- **Scale.** `find` reads every sidecar on every call, and `poll` reads one sidecar per inbox
  object. That suits libraries of a few thousand documents.
  - Beyond that, keep the namespaces in an index and point `find` at it. Options are S3 Metadata
    tables (queried with Athena), DynamoDB, or a database.
  - For `poll`, use S3 Event Notifications through SQS, with the queue position as the cursor.
- **Conditional writes.** `PutObject` with `IfMatch` / `IfNoneMatch` is assumed. General-purpose
  buckets support it since November 2024, with botocore of that date or later. Some
  S3-compatible stores do not support it; there a put fails or the condition is ignored.
- **ETag as version.** The ETag changes whenever an object is replaced with different bytes. A
  multipart upload of identical bytes with the same part size gives the same ETag, which is
  correct here.
- **No Office conversion.** Office files are passed on as they are, and the model call rejects
  them (unsupported media type). Store PDFs, or add a conversion step before upload.
- **Media types.** These come from the object's `Content-Type`. A generic
  `binary/octet-stream` / `application/octet-stream` falls back to a guess from the file
  extension.
- **Keys that look like sidecars.** An object whose key ends in `.docreview.json` is always
  treated as a sidecar, never as a document. Don't store real files under that suffix. The adapter
  would overwrite such an object as a sidecar if a document's sidecar key equalled it. The IAM policy
  above confines writes to that suffix, so no other object can be written.
